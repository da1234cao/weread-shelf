# 20轮差异化测试计划 — 用户场景模拟

## Round 1 ✅ — 新用户首次访问
- 打开首页(overview) → 浏览书架 → 点开有笔记的书 → 查看笔记详情 → 导出笔记

## Round 2 — 数据刷新场景
- 手动触发数据刷新 → 轮询刷新状态 → 刷新完成后检查书架/笔记/发现页数据一致性

## Round 3 — 统计浏览场景
- 浏览overview统计 → 切换周/月/年/总 → 翻看历史周期 → 对比不同时期阅读量

## Round 4 — 书架浏览场景
- 浏览完整书架 → 按分组查看 → 点开不同分组的书 → 看看每本书的笔记/想法

## Round 5 — 发现页探索
- 浏览发现页推荐 → 点开推荐书籍详情 → 导出推荐书的笔记（如果有）

## Round 6 — 登录认证场景
- 用正确密码登录 → 访问需要登录的页面 → 登出 → 用错误密码登录 → 验证被拒绝

## Round 7 — 笔记导出场景
- 找3本有大量笔记的书 → 分别导出markdown → 检查导出的格式/内容完整性

## Round 8 — 管理后台场景
- admin登录 → 查看设置 → 修改pull间隔 → 修改时区 → 查看用户列表 → 修改密码

## Round 9 — CLI使用场景
- 命令行执行pull → 用probe查看特定API数据 → 比较CLI和web返回数据是否一致

## Round 10 — 多周期统计对比
- 查看本周/本月/今年的阅读统计 → 翻到上月/去年的数据对比 → 验证趋势变化

## Round 11 — 书架变更场景
- 数据刷新后 → 对比前后书架书籍数量变化 → 检查新增/移除的书

## Round 12 — 想法&笔记回顾
- 打开笔记最多的书 → 逐章浏览高亮和想法 → 检查章节顺序 → 验证想法内容完整

## Round 13 — 用户管理场景(admin)
- 创建新用户 → 用新用户登录 → 验证权限 → 修改用户密码 → 删除用户

## Round 14 — 设置变更场景
- 修改retention_days → 触发prune → 修改gateway_interval → 修改模块可见性 → 验证变更生效

## Round 15 — 大数据量浏览
- 遍历所有有笔记的书的详情页 → 随机抽查10本 → 验证每本的数据完整性

## Round 16 — 多次刷新场景
- 连续触发2次刷新 → 验证并发保护 → 等完成后触发第3次 → 验证幂等

## Round 17 — API key管理
- 在admin页修改API key → 验证新key生效 → 测试无效key被拒绝

## Round 18 — 长会话场景
- 保持登录状态 → 依次访问所有页面 → 验证session不过期 → 操作流畅无异常

## Round 19 — 回归验证
- 重复Round 1+3+4的核心步骤 → 验证所有功能正常 → 对比数据变化

## Round 20 — 最终全量验证
- 完整测试所有端点 → 最终数据拉取 → 生成测试总结
