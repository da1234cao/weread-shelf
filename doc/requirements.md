# 微信读书看板 · 需求规格

> 本文是面向实现的需求规格。接口细节见 [api.md](api.md)，运行/部署见 [../README.md](../README.md)。

## 1. 目标

每天自动拉取自己的微信读书数据，存进本地 SQLite，以自托管 Web 看板展示**长期趋势**
（阅读时长、书架进度、笔记/划线增量、个性化推荐）——这些是官方 App 本身不长期保留的东西。
在此基础上增加一个**管理页面**，把过去只能用环境变量配置的行为搬到页面上可视化管理。

## 2. 数据来源

所有数据来自官方 skill 背后的 HTTP 网关，使用一个**长期有效**、自动绑定账号的 API Key
（`wrk-` 开头）。登录 https://weread.qq.com/r/weread-skills 生成，**在管理页填入**（§5.8），
不再使用 `.env`。接口清单与字段见 [api.md](api.md)。

## 3. 信息架构

顶部导航（公开页面）：

| Tab | 路由 | 说明 | 可隐藏 |
|-----|------|------|:------:|
| 概览 | `/` | 阅读统计与趋势 | ✅（管理页可关，默认显示） |
| 书架 | `/shelf` | 封面网格，按分组展示，**书可点开** | — |
| 笔记 | `/notes` | "有笔记的书"索引 | — |
| 发现 | `/discover` | 个性化推荐 | ✅（管理页可关，默认显示） |

新增 **书籍详情页** `/book/{book_id}`，是书架与笔记两条入口的统一落点（见 §4.3）。
管理入口 `/admin` 不在公开导航里，单独访问。

## 4. 页面要求

### 4.1 概览
维持现有：阅读时长曲线、书架进度、笔记/划线增量、偏好分析。可被管理页隐藏。

### 4.2 书架
维持现有网格 + 分组，但每本书**变为可点击**，跳转到该书的书籍详情页（§4.3）。

### 4.3 书籍详情页（核心改动）
路由 `/book/{book_id}`，是"书籍信息 + 个人笔记"的统一展示处。书架点书、笔记列表点书都到这里。

- **页头**：封面、书名、作者、阅读进度、分类/出版社、简介、划线/想法计数、导出 Markdown。
- **子标签**：`信息` / `划线(N)` / `想法(N)` 三个 tab：
  - `信息`：书籍基本信息（书名/作者/译者/分类/出版社/出版时间/ISBN/简介/评分等）。
  - `划线`：按章节分组的划线文本。
  - `想法`：按章节分组的个人想法（含被划线的原文摘录 + 想法正文）。
- 旧的 `/notes/{book_id}` 与导出逻辑并入此页（导出按钮保留）。
- **信息补全**：书架同步只给到书名/作者/封面；其余字段（简介/分类/出版社/出版时间/ISBN/评分）在
  **首次打开该书详情时**按需调 `/book/info`（公开数据，但仍走带 key 的网关，故需已配置 key）拉取并缓存进
  `book` 表，之后直接读库；以"是否已补全"为准，避免重复调用。

### 4.4 笔记
保留为**"有笔记的书"索引**（表格：书名/作者/进度/划线数/想法数）。点书名进入书籍详情页并默认停在 `划线` 子标签。

### 4.5 发现
维持现有推荐网格。可被管理页隐藏。

## 5. 管理页面 `/admin`

### 5.1 登录与管理员账号
- 管理员账号存于 DB，首次启动初始化为默认 `admin` / `admin`，**不再通过环境变量传入**。
- 首次用默认账号登录后，**强制**修改用户名与密码并保存到 DB；改完才放行其余管理功能（API Key 等敏感配置都在其后，默认弱口令不能长期暴露）。
- 管理员之后可随时在管理页修改自己的用户名与密码（与普通用户走同一套账号机制）。
- 管理页全部内容仅管理员可见可操作。

### 5.2 显示设置
- 是否显示「概览」模块，默认**显示**。
- 是否显示「发现」模块，默认**显示**。
- 关闭后：对应 tab 从导航中隐藏，直接访问其路由跳转到首个可见页面。
- 隐藏只影响前端展示；后台**仍照常拉取**这部分数据，重新开启即有完整历史（趋势不断档）。

### 5.3 访问控制
- 是否要求普通用户登录才能访问，默认**否**。
  - 关闭（默认）：除 `/admin` 外全部公开。
  - 开启：页面与数据接口（`/api/*`、`/export/*`）一并需登录，仅放行 `/api/health`、登录页与 `/static`；普通用户用各自账号，管理员账号也能登。

### 5.4 用户管理
- 管理员可创建 / 改密 / 删除普通用户（用户名 + 密码，密码加盐哈希存 DB）。
- 仅当 §5.3「需要登录」开启时，普通用户账号才派上用场。

### 5.5 拉取调度
- 用**间隔预设**配置定时拉取，档位为 **6 / 12 / 24 小时（默认 24）**，替代原先的 cron 表达式。
- 提供「立即刷新」按钮（沿用现有 `/api/refresh`，后台拉取、带运行中互斥）。
- **完成反馈**：点刷新后前端轮询 `/api/refresh/status`，直到本次同步结束再弹成功（附条数）/ 失败提示；
  打开页面时若已有后台同步在跑也会显示进度。交互细节见 [refresh-interaction.md](refresh-interaction.md)。
- 显示上次拉取时间 / 结果 / 错误（来自 `PullRun`）。
- 修改间隔后**无需重启**即可生效（重排调度任务）。

### 5.6 时区
- 在管理页设置时区，**不再通过环境变量传入**。时区只用于**日界**（按本地日聚合阅读时长、判定"今天"）；
  间隔调度从启动时刻起算，与时区无关。

### 5.7 skill_version 升级提示
- 网关响应可能带 `upgrade_info`（见 [api.md](api.md) §通用约定）。
- 每次拉取时检测并记录服务端建议的版本；当建议版本高于当前 `skill_version` 时，管理页显示升级提示。
- 管理员可在管理页更新当前 `skill_version`。

### 5.8 网关连接（API Key）
- 在管理页填入 `wrk-` 开头的 API Key，保存到 DB；不再用 `.env`。
- 字段**只写不回显**：已配置时显示「已配置 ✓」与「替换」操作，不展示原值。
- 保存前做格式校验（`wrk-` 前缀）并试调一次网关，给即时成功/失败反馈。
- 未配置 Key 时停用调度与拉取，公开看板照常提供（显示「尚未配置」），引导管理员去配置。
- CLI（`cli.py`）同样从 DB 读 key，需先在网页配置一次。

## 6. 配置与存储

**全部配置走 DB（管理页可改），不再有 `.env` 文件**；运行时只靠 Docker/compose 提供固定路径与端口。

| 配置 | 位置 | 默认 | 备注 |
|------|------|------|------|
| API Key | DB | —（首启未配置） | §5.8，管理页填入、只写不回显 |
| 管理员账号 / 密码 | DB | `admin` / `admin`（首次） | §5.1，首登**强制**修改 |
| 会话签名密钥 | DB | 首启随机生成 | §7，重启沿用 |
| 显示概览 / 显示发现 | DB | 是 / 是 | §5.2 |
| 需要普通用户登录 | DB | 否 | §5.3 |
| 拉取间隔 | DB | 24 小时 | §5.5，取代 `PULL_CRON` |
| 时区 | DB | `Asia/Shanghai` | §5.6，取代 `TZ` |
| `skill_version` | DB | `1.0.3` | §5.7，可被升级提示驱动更新 |

- 全部配置存 DB，首次启动用内置默认初始化；之后**以 DB 为准**。
- **不再有 `.env` 文件**，compose 去掉 `env_file`；原 env 变量 `WEREAD_API_KEY` / `PULL_CRON` / `TZ` / `SKILL_VERSION` 全部退役。
- DB 路径与端口仍由 Docker/compose 固定：容器内 `/data/weread.db`（Dockerfile `ENV`）、监听 `8765`（CMD），
  数据卷挂载与端口映射交给 `docker-compose.yml`。
- API Key 以明文存于 SQLite 数据卷（不做加密——解密密钥无处安放，反而引回 env），靠数据卷私有保证安全。

## 7. 认证模型

- 会话用签名 cookie（登录后下发，可注销）；签名密钥首次启动随机生成并存入 `app_settings`，重启沿用（不依赖 env）。
- 统一登录页 `/login`：管理员与普通用户共用，登录后按 `is_admin` 决定能否进 `/admin`。
- 管理员与普通用户**同表**，以 `is_admin` 区分；所有账号密码加盐哈希存储，不存明文。
- 保护规则：
  - `/admin/*`：始终要求 `is_admin` 身份。
  - 公开页面与数据接口：§5.3 关闭时全公开；开启时需任一有效用户或管理员（范围见 §5.3）。
