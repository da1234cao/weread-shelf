# 保活自愈（Health Monitor）

## 原理

容器运行 `--restart unless-stopped`，进程退出后 Docker 会自动重启。利用这个机制：后台线程定时探测自身的业务端点，连续失败则主动退出，让容器重启恢复。

## 工作方式

- 独立 daemon 线程，与应用同生共死
- 每隔 **60 秒** `GET /api/shelf`
- 状态码 >= 500 或请求失败（超时/连接拒绝）均视为异常
- 连续 **5 次**（= 5 分钟）异常后 `os._exit(1)`
- 任意一次正常则重置计数

## 管理

Admin 设置页「保活自愈」复选框，默认开启。关闭后线程继续运行但不计数，不会触发退出。

## 为什么探 `/api/shelf`

- 走完整链路：HTTP → FastAPI → SQLAlchemy → SQLite
- 纯读，没有副作用
- 无需认证（public path），避免 auth cookie 过期干扰
- 即使没有数据（空书架）也返回 200，不影响判断

## 误杀分析

- 阈值 5 分钟，偶发的 DB 锁竞争（通常秒级恢复）不会触发
- 真正的硬件故障、DB 损坏、进程卡死才会持续 5 分钟以上
- 容器重启通常在 1-2 秒内完成，对用户几乎无感知
