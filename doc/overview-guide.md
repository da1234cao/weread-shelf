# 阅读概览使用说明

「概览」是个人阅读统计页面。它把你的阅读数据按 **周 / 月 / 年 / 总** 四个时间维度组织,让你既能看当下,也能回顾任意历史周期。

本文从使用者视角介绍:页面有哪些内容、如何交互,以及这些数据是怎么拉取与展示的(不涉及任何实现细节)。

---

## 一、页面包含什么

### 1. 维度切换:周 / 月 / 年 / 总

页面顶部是四个标签——**本周、本月、本年、总计**。点击即可切换,下方所有指标与图表随之变化。

### 2. 每个维度的核心指标

| 指标 | 含义 |
|------|------|
| **阅读时长** | 该周期累计阅读时长,并附"日均阅读"。 |
| **读过本数** | 该周期内翻阅过的书籍数量。 |
| **读完本数** | 该周期内读完的书籍数量。 |
| **阅读天数** | 该周期内有阅读记录的天数。 |
| **笔记条数** | 该周期内新增的笔记(划线 / 想法)数量。 |
| **阅读时长分布** | 一张柱状图,直观呈现时间分布。 |

阅读时长分布图的粒度随维度自动调整:

- **周** —— 按天展示(7 根柱)
- **月** —— 按天展示(约 30 根柱)
- **年** —— 按月展示(12 根柱)
- **总** —— 按年展示

> 说明:数据来源对「周」维度只提供 时长 / 天数 / 日均 与分布,**不提供 读过 / 读完 / 笔记**。因此在「本周」标签下不显示这三项,属正常现象。

### 3. 总体偏好(固定区域,不随维度变化)

页面下方有一块固定的「总体偏好」,**始终基于你的累计(总计)数据**,不随上方维度切换而变化:

- **偏好分类** —— 各类目累计阅读时长占比(环形图)。
- **24 小时阅读分布** —— 一天里你更常在什么时段阅读(折线图)。
- **偏好作者** —— 阅读时间最多的作者。

之所以固定在"总计"口径,是因为这类长期偏好本就反映整体习惯,且数据来源也只在总计维度提供 24 小时分布与作者偏好。

---

## 二、如何交互

- **切换维度**:点顶部「周 / 月 / 年 / 总」。每次切换默认回到"当前"周期(本周 / 本月 / 本年)。
- **翻看历史**:在 周 / 月 / 年 维度,用左右箭头 `‹ ›` 翻到上一个 / 下一个周期——例如翻到 *2024 年*、*2025 年 3 月*、或某一周。顶部标题会显示当前所看的周期。
  - 向前最多翻到你微信读书账号的**注册周期**;再往前没有数据,箭头变灰不可点。
  - 不能翻到未来。
  - 「总计」是累计口径,没有"上一个 / 下一个",因此**不显示翻页箭头**。
- **刷新**:历史数据不会变化,无需手动操作;当前周期由系统定期自动更新。若想立刻更新今天的数据,可到管理页点击「立即刷新」。

---

## 三、数据是怎么来的、怎么更新的

### 来源

所有数据来自微信读书官方接口。你需要先在管理页填入自己的 API Key(在微信读书生成),系统才能代表你的账号拉取数据。

### 首次拉取:一次性抓取全部历史

填好 Key 后的第一次拉取,系统会把你账号**从注册到现在的全部周期**——每一周、每一月、每一年,以及总计——都抓取下来并保存到本地。

这样做的原因很简单:**历史数据不会再变化**(去年某个月读了多少是固定的),所以一次抓全、永久保存最划算,以后翻看也无需再次联网。

> 提示:如果你的账号阅读历史很长,第一次拉取需要逐个周期请求,可能耗时数分钟。它在后台进行,不影响你使用其它页面,管理页可以看到拉取进度。

### 后续更新:只刷新最新

此后每次定期(或手动)拉取,系统**只刷新当前周期**——再加上"刚结束的上一个周期"(用于跨周 / 跨月 / 跨年时把它的最终数字补齐)。早已固定的历史不再重复抓取,因此日常更新非常轻量、很快完成。

### 页面读取:只读本地,浏览时不联网

你在「概览」翻看任何周期时,页面都是**直接读取本地已保存的数据**,浏览过程中不会临时去访问微信读书。好处是:

- 翻看任意历史周期都**秒开**,没有等待;
- 即使此刻连接微信读书网关失败,也能照常查看已保存的数据。

### 数据流小结

```
填入 API Key
    ↓
首次拉取：抓取全部历史周期 → 保存到本地
    ↓
定期/手动拉取：只刷新当前(及刚结束的上一个)周期
    ↓
打开「概览」：直接读取本地数据展示
```
